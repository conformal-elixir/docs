# conformal-elixir/docs

Source for [Conformal Elixir Docs](https://www.conformal-elixir.com/), hosted on GitHub Pages.

## Projects

| Project | Responsibility | Site content |
| --- | --- | --- |
| [Beaver](https://github.com/beaver-lodge/beaver) | MLIR construction, transformation, and execution from Elixir | Generated API documentation at `/beaver/` |
| [Kinda](https://github.com/beaver-lodge/kinda) | Bind C libraries to the BEAM with Zig | Generated API documentation at `/kinda/` |
| [Batata](https://github.com/batata-lang/batata) | Elixir frontend, CLI, and host services | GitHub link |
| [Sluice](https://github.com/batata-lang/sluice) | Beaver-based MLIR/LLVM compiler provider | GitHub link |
| [BTT contracts and tools](https://github.com/batata-lang/btt-abi) | Shared data and validation, separate compiler and benchmark crates | GitHub link |
| [BTT Runtime](https://github.com/batata-lang/btt-runtime) | Execution kernel, term helpers, GC, and scheduling | GitHub link |

Private repositories are linked on GitHub. The workflow does not check them out,
build their documentation, or include their content in the published site.
The former `/batata/` API entry is a static GitHub link page; generated Batata
documentation is no longer included in deployments.

## Local preview

The homepage is plain HTML and CSS:

```sh
python3 -m http.server 8000
```

Open <http://localhost:8000>. The API documentation directories are generated by
the workflow and are not present in a source-only checkout.

## Build and deploy

GitHub Actions checks out public Beaver `main` and the compatible Kinda revision
from Beaver's `native-deps.json`. It installs the pinned LLVM/MLIR toolchain,
builds both projects with `mix docs`, and assembles a fresh Pages artifact with
the homepage and these two documentation directories.

Pull requests validate the full build. Changes to either HTML page, `CNAME`, or
the workflow on `main` build and deploy the site. A weekly schedule also refreshes
the public API documentation; **Actions → Build and deploy docs → Run workflow**
can trigger a rebuild. Only `main` deploys to GitHub Pages.
